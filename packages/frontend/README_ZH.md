## 项目概述

**法律智能工作台** 是一款融合**计算法学方法论**的专业诉讼分析平台，通过交互式数据可视化、LLM 增强分析与统计稳健性检验，为律所竞争力研究提供前所未有的透明度与洞察深度。

> **声明：** 本项目是基于 Mahari et al. (2025) 所述的基于结果排名算法的非官方开源实现，仅供教育与研究可视化用途。

### 核心创新

传统律所排名依赖声誉调查与营收规模——这些代理指标与真实诉讼胜绩往往弱相关。本平台引入**基于诉讼结果的排名方法论**，灵感源自：

- **Bradley-Terry 模型** — 源自体育分析的配对比较框架
- **AHPI（调整后对抗绩效指数）** — 为法律对抗场景设计的新颖指标
- **网络分析** — 图论方法映射律所竞争生态

**学术对齐：**
- *Nature Computational Science*：数据驱动的律所排名（将每场诉讼视为原告/被告律所的配对博弈）
- *Federal Sentencing Reporter*：符合欧盟 AI 法案的可解释、可追溯分析流程

## 核心功能

### 1. 多视图交互可视化引擎

| 视图 | 功能描述 |
|------|----------|
| **力导向网络图** | 原告-被告关系的动态图可视化，支持物理模拟与拖拽交互 |
| **邻接矩阵热力图** | 用于识别密集竞争模式的矩阵视图 |
| **统计点图** | 按案件类型、法院的分布分析 |
| **数据表格** | 可排序、可筛选、实时搜索的表格界面 |

### 2. AI 驱动的法律智能分析

- **LLM 集成** — 兼容 OpenAI 标准 API，支持流式响应
- **数据锚定洞察** — 将筛选后的案件数据（CSV）注入提示词，避免幻觉
- **结构化输出解析** — 从 LLM 响应中提取实体、论断与证据引用
- **六阶段推理可视化** — 实时展示 AI 思考过程：解析提示词 → 构建上下文 → 检索知识 → 推理分析 → 生成响应 → 验证质量
- **Think Block 解析** — 分离推理痕迹与最终输出，保障透明度

### 3. 稳健性与可复现框架

- **敏感性分析** — 多参数变体测试
- **空对照检验** — 基于随机化的显著性检验（p 值计算）
- **证据可追溯** — 每条结论关联具体案件记录（RowId）
- **导出能力** — Markdown 报告与 JSON 数据，便于同行评议
- **URL 状态同步** — 通过可分享链接复现完整分析

### 4. 双模式界面

- **J2 神经指挥台** — 沉浸式演示界面，适合路演与会议展示
- **工作台模式** — 完整功能的深度分析环境
- **无缝嵌入** — iframe 兼容架构，支持企业级集成
- **深色/浅色主题** — 专业外观，适配任何场景

### 5. 多 Agent 分析架构（J2 风格）

平台实现了**验证优先的多 Agent 流水线**，将复杂的法律分析拆解为专业化、可编排的 Agent：

```
┌──────────────────────────────────────────────────────────────┐
│  🖥️  J2 神经指挥台（打字机动画）                               │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐          │
│  │  Agent 1    │  │  Agent 2    │  │  Agent 3    │          │
│  │  知识库加载  │→ │  证据核验   │→ │  综合生成   │→  ...    │
│  │             │  │             │  │             │          │
│  └─────────────┘  └─────────────┘  └─────────────┘          │
│       ↓                ↓                ↓                    │
│    进度条           进度条           进度条                   │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│  [打开工作台 →]  深度链接，分析状态已同步                       │
└──────────────────────────────────────────────────────────────┘
```

**Agent 流水线：**

| Agent | 职责 | 状态 |
|-------|------|------|
| **Agent 1 · 知识库加载** | 加载 Harvard CAP 数据库，同步 60,000+ 诉讼记录 | ✅ 已实现 |
| **Agent 2 · 证据核验** | 交叉引用判例，验证引用完整性，幻觉检测 | ✅ 已实现 |
| **Agent 3 · 综合生成** | 计算贝叶斯推理，生成置信度评分，神经综合 | ✅ 已实现 |
| **Agent 4 · 工作台交接** | 传递分析状态，深度链接至 Explorer，筛选条件已预填充 | ✅ 已实现 |

**核心特性：**
- **验证优先流水线** — 每条论断在展示前均经 Harvard CAP 验证
- **证据绑定论断** — 所有洞察关联具体案件 ID
- **幻觉检测** — 零容忍策略，可视化验证徽章
- **置信度评分** — 贝叶斯推理与不确定性量化
- **无缝交接** — 一键从演示切换至完整工作台，状态完整保留

该架构确保**可解释、可审计、可信赖**的法律智能——对于企业合规与法规遵从（欧盟 AI 法案）至关重要。

## 快速开始

### 环境要求

- Node.js 18+（推荐 LTS 版本）
- pnpm 8+（推荐）或 npm

### 安装与启动

```bash
# 克隆仓库
git clone https://github.com/your-org/legal-intelligence-workbench.git
cd legal-intelligence-workbench

# 安装依赖
pnpm install

# 启动开发服务器
pnpm dev
```

### 演示模式

适用于稳定的现场演示，预加载示例数据：

```bash
pnpm dev:demo
```

或在任意 URL 后添加 `?demo=1`。

### 环境配置

创建 `.env.local` 文件配置 LLM（可选）：

```env
VITE_LLM_API_URL=https://api.openai.com/v1
```

> **注意：** 若 `VITE_LLM_API_URL` 为空或 API 请求失败，系统将自动回退到**演示 Mock 输出**，包含逼真的思考痕迹与结构化论断。

### 生产构建

```bash
pnpm build
pnpm preview
```

## 数据输入

### 支持格式
- CSV（逗号分隔）
- TSV（制表符分隔）

### 字段映射

| 字段 | 必填 | 说明 |
|------|------|------|
| `Plaintiff firm` | 是 | 代表原告的律所 |
| `Defendant firm` | 是 | 代表被告的律所 |
| `Case type` | 否 | 案件类型（如专利、反垄断） |
| `Court` | 否 | 管辖法院 |
| `Outcome` | 否 | 案件结果，用于分层分析 |
| `Weight` | 否 | 边权重，用于可视化（默认为 1） |

### 示例数据

界面内置示例数据集：
- **快速演示** — `mahari_lawsuits_example.csv`
- **Fig.2 源数据** — `mahari_fig2_moesm4_interactions.csv`

## 证据追溯系统

每条分析结论均可追溯至原始证据：

- **RowId 关联** — 点击任意洞察可展示源记录
- **视图联动高亮** — 选中的边在所有视图中同步高亮
- **导出证据链** — JSON 导出包含完整证据引用
- **审计轨迹** — 通过 URL 状态完整复现
